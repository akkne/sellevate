# Изоляция организаций

Организация — единица изоляции. Платформенная роль находится в `role`, членство и роль внутри организации — в `org_id` и `org_role`. Клиентские заголовки идентификации шлюз удаляет. Доверенный заголовок заполняет `ITenantContext` для запроса. Защищённый маршрут проверяет политику и объект, обработчик не берёт идентификатор организации из произвольного тела запроса.

В PostgreSQL глобальный фильтр EF ограничивает обычные запросы, RLS действует также для прямого обращения к таблице. Транзакция задаёт tenant через `SET LOCAL`. Роли приложения и миграций имеют разные права. В MongoDB выборки включают организацию, ключи Redis содержат её идентификатор. Для компаний требуется также владелец.

Сообщение Kafka переносит организацию в envelope. Данные старого сообщения проверяются по контракту потребителя. Обслуживание нескольких организаций оформляйте как системный проход с явной областью для каждой записи. Порядок включения RLS, запросы проверки и откат находятся в [руководстве раскатки](../../infra/tenancy/README.md).
