# Стиль кода

## Общие правила

- Пиши короткий, понятный код без очевидных комментариев, заглушек и неиспользуемых файлов. Файлы адаптеров отключённых AI-моделей сохраняй по [правилу интеграций](integrations/README.md).
- Называй сущности по предметной области проекта.
- На границах сценариев используй контракты, затем инфраструктурные реализации. Сценарии не зависят от HTTP-фреймворка, ORM и SDK провайдеров.
- Держи секреты и локальные значения вне кода, в неотслеживаемом `.env`. После появления приложений перечисли нужные переменные в `.env.example`. Публичные переменные Next.js не должны содержать секреты.
- При изменении поведения обновляй документацию и проверяй затронутый сценарий.
- Указывай типы на публичных границах. Применяй согласованные форматтер и линтер.
- Обрабатывай ошибки явно. Сохраняй контекст ошибки и возвращай понятный результат.
- Серверные тесты размещай в `tests/backend/`, клиентские в `frontend/__tests__/`. Проверяй изменённый сценарий и ошибки через его публичный контракт.

## Next.js и Tailwind CSS

- Для каждого пользовательского текста указывай русский и английский варианты. Используй общий механизм перевода на клиенте и сервере. Проверяй также пустые состояния, загрузку, ошибки, подсказки и aria-подписи. Отделяй переводимые подписи от значений API и пользовательских данных.
- Используй TypeScript для нового интерфейса. Компоненты делай небольшими и называй по назначению.
- Все экраны и компоненты в `frontend/` оформляй утилитами Tailwind CSS 4 в `className`. Для адаптивной вёрстки, фокуса, выбора и отключённых элементов используй варианты Tailwind. В условиях указывай полные имена классов, чтобы сборщик мог их обнаружить.
- Цвета и тени обеих тем задавай в общей таблице стилей и подключай через `@theme inline`. Следуй [дизайн-системе](design-system.md). Повторяющиеся наборы утилит для кнопок, полей и панелей вынеси в общие стили.
- Для значения, которое становится известно только при рендеринге, передавай данные через CSS-переменную и применяй её в статической утилите Tailwind.
- Размещай секреты и серверные вызовы в серверном окружении Next.js. Клиентскому коду передавай только необходимые данные.
- Учитывай доступность: семантическая разметка, подписи полей, управление с клавиатуры, видимый фокус и состояния загрузки/ошибки.


Команды приведены в [Git-процессе](git/README.md).

## C# в Sellevate

Группируйте код по предметной области внутри сервиса. Интерфейс обозначайте префиксом `I`, асинхронный метод — суффиксом `Async`. Настройки считывайте через типизированные options. Передавайте CancellationToken до внешнего вызова. Сервисы и инфраструктуру документируйте XML-комментариями там, где нужно объяснить контракт. Имена и отступы проверяет [EditorConfig](../.editorconfig).

Регистрация DbContext использует область HTTP-запроса. Пул контекстов несовместим с захваченным контекстом организации. Вызов платного провайдера проходит через AI-сервис и учёт использования. Проверки архитектуры контролируют ссылки проектов и зависимости контрактов от ORM, HTTP, транспортов и реализаций. Приёмка маршрутов сравнивает атрибуты контроллеров с конфигурацией YARP.
